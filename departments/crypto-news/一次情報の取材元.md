# 一次情報の取材元

毎日、上から順に見る。**発表した本人が出している場所**だけを並べてある。
ニュースサイトはここに載せない。記事から入ったときも、必ずこの表のどこかまで戻る。

## 5. チェーン上のデータ（一次情報に準ずる）

| 取材元 | 何が出るか |
|---|---|
| ブロックエクスプローラ | 送金・保有・発行の事実 |
| ステーブルコイン発行体の準備金報告 | 裏付け資産の構成 |
| 監査法人の証明報告書 | 発行体の残高 |

**チェーン上のデータは事実だが、意味づけは推測になる。**
「大口が動いた」までは書ける。「だから下がる」は書かない。

## 裏取りの手順

1. その日付いた発表を探す
2. 発表元の公式ページを開く
3. **発表日を確認する**。記事の日付ではなく、発表文に書かれている日付を見る
4. 数字を発表文から直接写す
5. 出典URLを控える

### この環境での確認のしかた

外部ページへの直接取得（`WebFetch`）は、通信の出口で塞がれている先がある。
塞がれたときは `WebSearch` の `allowed_domains` に公式ドメインだけを指定して引く。
検索結果に出典元のドメインが出れば、そこが発表元だと確認できる。

例：`allowed_domains` に `sec.gov` と `federalregister.gov` だけを入れて検索する。
こうすると、ニュースサイトの記事が混ざらない。

**直接開けなかったことを理由に、二次情報で代用しない。**
検索でも発表元に届かなかったものは、その旨を書いて5件から外す。

## 更新の目安

制度の側は、窓口や名前が変わる。**半年に一度、リンクが生きているかを見る。**
死んでいたら差し替え、差し替えた日を追記ログに残す。
