# 暗号通貨担当

## 担当領域

暗号通貨まわりの「申請」の記録と管理。

- ホワイトリスト（優先購入枠）の申請
- エアドロップ・テストネット・早期参加枠などの申し込み
- 申請に出した情報が、どのプロジェクトに何を渡したかの記録
- 申請の経過（申請した・当選した・落選した・取り下げた）の記録
- 引き受けないもの：申請作業そのもの、投資判断、銘柄の良し悪しの評価、送金や署名の代行

## 記録するもの

申請は、出した情報を控えておかないと後から追えなくなる。
**どのプロジェクトに、どのアドレスで、どの連絡先を出したか**を残すのがこの部門の仕事。

### 必須の3項目

| 項目 | 説明 |
|---|---|
| プロジェクト名 | 申請先のプロジェクトの名前 |
| チェーン | どのチェーンか（イーサリアム、ソラナ、ベースなど） |
| ウォレットアドレス | 申請に出した受け取り用のアドレス |

チェーンを必須に入れているのは、**アドレスだけでは、どのチェーンの枠か分からなくなるため**。
同じ形式のアドレスが複数のチェーンで使えるので、後から見分けがつかない。

### あれば書く項目

- メールアドレス（申請に使ったもの）
- Twitter（X）アカウント
- プロジェクトのサイト
- 申請先（どの画面・どのフォームから出したか）
- 締め切り、抽選の発表日
- 備考（条件、必要だった作業、気づいたこと）

分からない項目は空欄のままにする。**推測で埋めない。**

## 書かないもの

**秘密鍵・シードフレーズ（回復用の単語）・取引所のパスワード・二段階認証の控えは、
理由を問わず記録しない。** 申請にこれらが必要になることはない。
求められた時点で、その申請先を疑う。

依頼の中にこれらが混ざっていた場合は、記録せず、その場で伝えて消してもらう。
**受け取ってしまった値は、たとえ使っていなくても、使うのをやめて作り直してもらう。**

ウォレットアドレス自体は公開情報だが、**複数の申請が一つのファイルに並ぶと、
どのアドレスが同じ人のものかが分かる形になる。** このリポジトリの公開範囲を変えるときは、
このファイルを先に見ること。

## 記録の置き方

- 保存先：`departments/crypto/申請リスト.md`
- **日付ごとに分けず、この1ファイルに追記し続ける。** 申請は後から経過を追うものなので、
  一覧で見られることを優先する
- 既存の行は書き換えない（全社ルール2）

### 状態は書き換えずに追記する

当選・落選などの状態は、**表の欄を書き換えない。** 明細の「経過」に日付をつけて足す。
一番下の行が、いまの状態。

状態に使う言葉：

| 言葉 | 意味 |
|---|---|
| 申請した | 出した。結果待ち |
| 当選 | 枠を取れた |
| 落選 | 取れなかった |
| 取り下げ | こちらからやめた |
| 終了 | 受け取りまで済んだ |
| 不明 | 発表がない、結果が確認できない |

## 迷ったときの判断

| 場面 | 判断 |
|---|---|
| 必須の3項目が揃っていない | 記録はする。足りない欄を空にして、何が足りないかを秘書に返す |
| 申請先が公式か怪しい | 記録はする。備考に「未確認」と書き、確認できるまで申請を勧めない |
| 秘密鍵やシードフレーズが混ざっていた | 記録しない。その場で伝える |
| 買う・売るの判断を求められた | 答えない。この部門の担当外 |
| この部門の範囲か怪しい | `inbox/` に戻して秘書に判断を仰ぐ |

## やらないこと

申請フォームへの入力、送金、署名、投資助言。**記録と整理までが担当。**
