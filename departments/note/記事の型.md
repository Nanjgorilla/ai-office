# 100円記事の型

noteの有料記事（100円）を書くときの決まりごと。毎日5本、この型で書く。

100円は、読者が「外したら惜しい」とは思わない額。だから**買う前の期待値を上げすぎない**。
盛った見出しで買わせると、次の日から読まれなくなる。狙うのは一発ではなく、毎日読まれること。

## 記事の構成

無料部分で「何が起きたか」を渡しきる。有料部分で「だから自分はどうなるのか」を渡す。

| 節 | 内容 | 目安 | 許容幅 |
|---|---|---|---|
| 1 | つかみ。何が起きたかを一息で | 300字 | 240〜360 |
| 2 | 事実。日付・数字・出典を並べる | 400字 | 320〜480 |
| — | **ここから有料** | | |
| 3 | なぜそうなったか。仕組みを開く | 700字 | 560〜840 |
| 4 | 自分に何が起きるか。読者の生活につなぐ | 700字 | 560〜840 |
| 5 | ではどうするか。打ち手を並べる | 600字 | 480〜720 |
| 6 | 見ておく数字。次に何を確認するか | 300字 | 240〜360 |
| 7 | 出典と免責 | 200字 | 160〜240 |

合計は **2,800〜3,600字**。節1と2（無料部分）は700字前後に収める。

### 有料ラインをどこに置くか

**無料部分だけ読んで「知った」で終われる状態にする。** 途中で切らない。

事実を隠して切ると、読者は「出し惜しみされた」と感じる。事実は無料で渡し、
その事実の**読みかた**を有料にする。100円ぶんの値打ちは、情報そのものではなく整理にある。

## 見出しの作りかた

- 30字前後。スマホの一覧で切れない長さ
- 数字を一つ入れる。「1,259円安」「235円」のように、具体的なものを
- 断定的な予言を置かない。「暴落する」「必ず上がる」は使わない
- 問いの形は一日一本まで。5本すべてが「なぜ〜か」だと並んだときに見分けがつかない

| 良い | 良くない | 理由 |
|---|---|---|
| ガソリン235円の試算が出た日に、家計側でできること | 【衝撃】ガソリン235円時代へ！ | 煽りで買わせている |
| 1,259円安の日に、保険と海運だけが上がった理由 | 日経平均、暴落の始まりか | 予言になっている |

## 書きかた

- 一文は短く。**60字を超えたら切る**
- 段落は3〜4行で改行を入れる。スマホで読まれる前提
- 専門語は、初出のその場で開く。「ホルムズ海峡（中東の原油が通る出口）」
- 数字には必ず**いつ時点か**を付ける。「11日終値で」「10日時点で」
- 読者を「あなた」と呼ぶのは節4と5だけ。全編で呼ぶと説教くさくなる
- 自分の推測は「〜と思う」「〜の可能性がある」と分かる形で書く。事実と混ぜない

## 出典の書きかた

節7に、使った出典を**媒体名・記事の趣旨・日付**で並べる。

```
- 時事ドットコム「米原油先物が100ドル突破」2026年9月10日
```

数字を一つでも使ったら、その出どころを必ず載せる。孫引きになるときは、
孫引きだと分かるように書く。**出典を書けない数字は、記事に入れない。**

## 免責

相場・家計・健康に関わる記事には、節7の末尾にこの趣旨を入れる。文言は記事ごとに整えてよい。

> この記事は2026年◯月◯日時点で公開されている情報をまとめたものです。
> 将来の値動きや結果を保証するものではなく、特定の商品の売買を勧めるものでもありません。
> 最終的な判断はご自身でお願いします。

## 公開前の点検表

1本ごとに、上から順に見る。**一つでも欠けたら公開しない。**

| # | 見るところ | 落ちていたら |
|---|---|---|
| 1 | 数字すべてに出典と日付が付いているか | 出典を足すか、その数字を落とす |
| 2 | 出典は一次情報に近いか。まとめの孫引きで止まっていないか | 一次情報を当たり直す |
| 3 | 断定的な将来予測が入っていないか | 「〜の可能性がある」に直す |
| 4 | 投資・医療・法律の助言になっていないか | 判断材料を並べる形に戻す |
| 5 | 他人の文章をそのまま使っていないか | 事実だけ引いて書き直す |
| 6 | 無料部分だけで「何が起きたか」が分かるか | 事実を無料側に移す |
| 7 | 見出しが煽りになっていないか | 数字のある落ち着いた形に直す |
| 8 | 個人を特定して責める内容になっていないか | 題材ごと差し替える |
| 9 | 免責が入っているか（相場・家計・健康の記事） | 足す |
| 10 | 合計字数が帯に入っているか | 節の目安を見て増減する |

字数の実測は、道具を持っている側が行う。**推定値を書かない。**

## noteに出すときの付属情報

本文とは別に、投稿画面で入れるものが三つある。記事を書いたら一緒に用意する。

| 項目 | 決めかた |
|---|---|
| 価格 | 100円。変える話が出たら秘書に上げる |
| ハッシュタグ | 3〜5個。題材そのものを指す語を2個、読者層を指す語を1〜2個 |
| 見出し画像 | noteの組み込み画像から選ぶ。人物写真は避ける |

ハッシュタグは、記事ファイルの**本文より前**に置く。本文の字数に混ざらないようにするため。

## 貼り付け用に変換する

記事ファイルはMarkdownで書くが、noteの編集画面はMarkdownをそのまま解釈しない。
`##` や `**` を貼ると、記号がそのまま残る。

そこで、貼り付け専用の形に変換してから人に渡す。

```
python3 departments/note/貼り付け用に変換.py 2026-09-11
```

`YYYY-MM-DD_貼り付け用.md` が出る。記号を落とし、無料パートと有料パートを分け、
どの行を見出しにするかの一覧を付けたもの。**貼る順番どおりに並んでいる。**

変換は毎日かける。手で作り直さない。手で作ると、記事と貼ったものがずれる。

### 自動投稿はしない

noteには記事投稿の公式APIがない。出回っている自動投稿ツールは、
Web版が内部で使っているエンドポイントを解析したもので、仕様変更で壊れる。
規約上も、自動化された不正なアクセスと判断されればアカウントが止まる。

**売上が乗ったアカウントを賭ける取引になるので、やらない。**
公開の操作は人がする。時間をずらしたいときは、noteの予約投稿機能を使う。

## この型にない手順を足さない

点検表にない観点で止めない。足りないと思ったら、**この型に追記してから**使う。
その場の思いつきで基準を増やすと、日によって通る記事と通らない記事が変わる。

## ルールの追記ログ

- [2026-09-11] 初版。7節構成、合計2,800〜3,600字、無料部分は節1と2で700字前後と定めた。
  有料ラインは「事実は無料、読みかたは有料」の位置に置く。点検表10項目を置いた。
- [2026-09-11] noteに出すときの付属情報（価格・ハッシュタグ・見出し画像）と、
  貼り付け用への変換手順を追加した。ハッシュタグは本文の字数に混ざらないよう本文より前に置く。
  自動投稿は、公式APIがなく規約上のリスクがあるため行わないと明記した。
